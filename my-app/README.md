# Библиотека алгоритмов

Клиент React для REST API проекта. Пользователи хранятся в PostgreSQL, а
алгоритмы вместе с вложенными критериями — в MongoDB Atlas.

## Запуск

1. В корне проекта настройте `.env` для PostgreSQL и JWT:

   ```env
   DATABASE_URL=postgres://user:password@localhost:5432/database
   JWT_SECRET=replace-with-a-long-random-secret
   PORT=3000
   ```

   MongoDB Atlas URI задайте через `MONGODB_URI` в `.env` либо используйте
   предоставленный локальный `atlas-credentials.env`. Не добавляйте реальные
   учетные данные в Git.

2. Установите серверные зависимости, примените миграции PostgreSQL и перенесите
   старые алгоритмы (если таблица еще существует):

   ```bash
   npm install
   npx sequelize-cli db:migrate
   npm run migrate:algorithms
   npm run dev
   ```

   Команда переноса проверяет, что все карточки записаны в MongoDB, и только
   после этого удаляет таблицу `algorithms` из PostgreSQL. После переноса
   PostgreSQL используется только для пользователей.

3. В отдельном терминале запустите клиент:

   ```bash
   cd my-app
   npm install
   npm run dev
   ```

## Запуск в Docker

Из корня проекта соберите и запустите frontend, backend, PostgreSQL и MongoDB:

```bash
docker compose up --build
```

Откройте frontend на `http://localhost`. Backend доступен на
`http://localhost:3000`, проверка состояния — `http://localhost:3000/health`.
При первом запуске backend применяет миграции PostgreSQL автоматически.
Состояние контейнеров можно проверить командой `docker compose ps`; остановить
сервисы — `docker compose down` (данные в volumes при этом сохраняются).

Для локального стенда используются значения подключения и JWT-секрет по
умолчанию. Переопределите `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`
и `JWT_SECRET` в корневом `.env`, если нужны другие значения. Эти настройки
предназначены только для разработки; реальные секреты не добавляйте в Git.
Порты frontend/backend можно изменить через `FRONTEND_PORT` и `BACKEND_PORT`.

Vite проксирует `/api` на `http://localhost:3000`, поэтому браузеру не требуется
отдельная настройка CORS. Если сервер запущен на другом адресе, задайте
`VITE_DEV_API_PROXY_TARGET` в `my-app/.env`. При необходимости URL API можно
переопределить через `VITE_API_URL` (по умолчанию `/api`).

## Возможности

- JWT-регистрация и вход; access/refresh-токены сохраняются в браузере.
- MongoDB CRUD каталога с поиском, индикацией загрузки, сообщением об ошибке и
  кнопкой повтора.
- Добавление, изменение и удаление с оптимистичным обновлением и откатом при
  ошибке сервера.
- До 50 вложенных критериев на алгоритм; длина названия критерия — до 100,
  описания — до 2000 символов. Название алгоритма ограничено 100 символами,
  описание — 1000, поиск — 100;
  имя аккаунта и пароль также проверяются на клиенте и сервере.
- Одно дополнительное улучшение: поиск по названию, типу и описанию выполняется
  на сервере после паузы 350 мс после ввода.
- Компоненты формы, авторизации, списка и карточки алгоритма вынесены в отдельные
  файлы в `src/components`.
- У сортировки можно сохранить Python-код и опубликовать его в отдельной вкладке
  «Сортировки». Публичный каталог доступен без входа; код приватных алгоритмов
  отдаётся только их владельцам.
- Владелец публичной сортировки получает WebSocket-приглашение, когда другой
  пользователь выбирает его алгоритм для соревнования. Входящее приглашение
  можно принять или отклонить прямо на странице; принятие автоматически
  соединяет участников. Оба алгоритма должны быть публичными, а их владельцы —
  находиться онлайн. Приглашения хранятся в памяти сервера и не доставляются
  пользователям, которые были офлайн во время отправки.
- После готовности обоих браузеры получают общий массив, запускают свои
  Python-генераторы и передают шаги сортировки друг другу. Сервер не исполняет
  и не рассылает код.
- Для визуализации код должен определять генератор
  `sort_steps(values)`, который выдаёт копию массива после каждого шага через
  `yield`. Код выполняется в Web Worker на Pyodide/WASM, без Python-импортов,
  с ограничением времени выполнения и числа шагов. Сервер отдаёт файлы Pyodide
  по `/pyodide`; для WebSocket reverse proxy должен поддерживать upgrade
  соединений на `/ws/sort`. Очередь соревнований хранится в памяти одного
  процесса Node.js.
- Перед сохранением кода сортировки браузер компилирует его и проверяет
  результат на нескольких тестовых массивах. В комнате соревнования участники
  могут переписываться через WebSocket-чат; сервер ограничивает длину сообщения
  500 символами.
